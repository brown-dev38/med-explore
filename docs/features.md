# ฟีเจอร์และการทำงาน (Features)

## 1. บทบาทและแดชบอร์ด

| บทบาท | เงื่อนไขเข้าแดชบอร์ด | เมนู sidebar |
| --- | --- | --- |
| **ADMIN** | บทบาท `ADMIN` | ภาพรวม · ปีการศึกษา · ผู้ใช้งาน · กิจกรรม · โปรไฟล์ |
| **ORGANIZER** | สิทธิ์ `activity.manage` | กิจกรรมที่จัด · โปรไฟล์ |
| **STUDENT** | ล็อกอินทั่วไป | ภาพรวม · กิจกรรมที่จะมาถึง · ลงทะเบียนกิจกรรม · กิจกรรมของฉัน · โปรไฟล์ |

ผู้ใช้แต่ละคนมีได้ **1 บทบาทเท่านั้น** (`ADMIN`, `ORGANIZER` หรือ `STUDENT`) ฟอร์มเพิ่ม/แก้ไขเลือกได้ครั้งละหนึ่งบทบาท API ไม่รับรายการบทบาทว่างหรือหลายบทบาท และฐานข้อมูลบังคับ `user_roles.user_id` ไม่ให้ซ้ำ

โครงแดชบอร์ดใช้ `components/dashboard-shell.tsx` ร่วมกัน (sidebar + drawer บนจอเล็ก + บล็อกผู้ใช้/ปุ่มออกจากระบบ) และไฮไลต์เมนูปัจจุบันด้วย `usePathname()` (ห่อ `<Suspense>`)

## 2. การเข้าสู่ระบบ / ออกจากระบบ

- หน้า `/register` สำหรับนิสิตสมัครด้วยตนเองเท่านั้น บังคับกรอกรหัสนิสิตทั้งฟอร์มและ API และสร้างพร้อมบทบาท `STUDENT` เท่านั้น ผู้จัดกิจกรรมและพนักงานให้ ADMIN เพิ่มผ่าน `/admin/users` โดยรหัสนิสิตในฟอร์มของ ADMIN ยังไม่บังคับ

1. ผู้ใช้กรอก **ชื่อผู้ใช้ / รหัสนิสิต / อีเมล** + รหัสผ่าน ที่ `/login`
2. ระบบ POST ไป `/api/auth/callback/credentials` (relative) แล้วอ่าน session
3. เด้งไปแดชบอร์ดตามบทบาท (`dashboardPathFor`): `ADMIN → /admin`, `ORGANIZER → /organizer/activities`, อื่น ๆ → `/dashboard`
4. ผู้ที่ล็อกอินแล้วเข้า `/`, `/login`, `/register` จะถูก `proxy.ts` เด้งไปแดชบอร์ดของตน
5. ออกจากระบบ → ล้าง session แล้วกลับหน้าแรก (ซึ่งจะแสดง landing ให้ผู้ที่ยังไม่ล็อกอิน)

## 3. จัดการปีการศึกษา (`/admin/academic-years`)

- สร้างปีการศึกษา (ฉบับร่าง `DRAFT`) กำหนดรหัส + ช่วงวันที่
- **เปิดใช้งาน (ACTIVE)** ได้ทีละ 1 ปี — เปิดปีใหม่จะปิดปีที่ ACTIVE เดิมอัตโนมัติ (transaction)
- **ปิดปี (CLOSED)** / **เปิดใหม่ (กลับเป็น DRAFT)**
- แก้ไขรหัส/วันที่ได้เฉพาะปีที่ยังไม่ CLOSED
- **ADMIN ลบได้ทุกสถานะ** (`DRAFT` / `ACTIVE` / `CLOSED`) หลังยืนยันใน modal; ลบกิจกรรม ผู้เข้าร่วม เวลา QR ดาว แบบประเมิน และข้อมูลรางวัล/การแลกรางวัลที่ผูกกับปีนั้นใน transaction เดียว โดยคง Audit Log ไว้ หากลบปี ACTIVE ต้องเปิดใช้งานปีอื่นเอง

## 4. จัดการผู้ใช้งาน (`/admin/users`)

- ค้นหา (username/อีเมล/รหัสนิสิต/ชื่อ-นามสกุล), กรองบทบาท, แบ่งหน้า
- **ADMIN เพิ่มผู้ใช้งานได้** ผ่านปุ่ม "เพิ่มผู้ใช้งาน" ใน `/admin/users`: ชื่อผู้ใช้ อีเมล รหัสผ่านเริ่มต้น/ยืนยันรหัสผ่าน ชื่อ-นามสกุล รหัสนิสิต บทบาทหนึ่งบทบาท และสถานะบัญชี
- ตรวจชื่อผู้ใช้/อีเมล/รหัสนิสิตซ้ำ รหัสผ่านอย่างน้อย 6 ตัวอักษร เก็บเฉพาะ bcrypt hash และสร้างผู้ใช้ บทบาท และ Audit Log ใน transaction เดียว
- แก้ไขชื่อ-นามสกุล/รหัสนิสิต, เปิด-ปิดการใช้งาน
- เปลี่ยนบทบาท (ADMIN / ORGANIZER / STUDENT) โดยแทนที่บทบาทเดิม — ห้ามเปลี่ยน ADMIN คนสุดท้ายเป็นบทบาทอื่น
- ปิดบัญชี (`isActive=false`) แล้วล็อกอินไม่ได้
- checkbox "เปิดใช้งานบัญชี" ถูกล็อกเมื่อแก้ไขบัญชีตัวเองหรือ ADMIN คนสุดท้ายที่เปิดใช้งาน พร้อมแสดงเหตุผล; API ป้องกันการปิดบัญชีตัวเอง และการปิด/เปลี่ยนบทบาท ADMIN จนไม่เหลือ ADMIN ที่เปิดใช้งาน โดยตรวจใน transaction แม้ไม่ส่ง `roles` มาด้วย
- **ADMIN ลบผู้ใช้งานได้** ผ่านปุ่ม "ลบ" และ modal ยืนยัน; ห้ามลบบัญชีตัวเองหรือ ADMIN คนสุดท้ายที่เปิดใช้งาน และหากมีประวัติกิจกรรม/การทำรายการจะป้องกันการลบพร้อมแนะนำให้ปิดใช้งานแทน บัญชีที่ลบได้จะถูกลบพร้อมบทบาทและบันทึก Audit Log ใน transaction เดียว
- บัญชีที่ถูกลบหรือปิดใช้งานใช้ session เดิมเข้าถึงข้อมูลหรือ API ไม่ได้ และกลับหน้าเข้าสู่ระบบได้โดยไม่วน redirect
- ขณะเปิดหน้าใช้งาน ระบบตรวจ session ทุก 5 วินาที และตรวจเมื่อกลับมาเปิดแท็บ/เชื่อมต่ออินเทอร์เน็ตอีกครั้ง หากถูกระงับจะออกจากระบบอัตโนมัติและแสดง modal "บัญชีของคุณถูกระงับ" ค้างไว้ พร้อมข้อความติดต่อผู้ดูแลและปุ่ม "กลับไปหน้าเข้าสู่ระบบ" โดยหยุดตรวจซ้ำขณะ modal เปิด เมื่อกดแล้วจะไปหน้าเข้าสู่ระบบโดยไม่แจ้งซ้ำ หากถูกส่งไปหน้าเข้าสู่ระบบพร้อมเหตุผลระงับโดยตรงจะแสดง modal เดียวกันให้กด "รับทราบ" โดยแยกจากบัญชีถูกลบและเซสชันหมดอายุ; การเชื่อมต่อขัดข้องชั่วคราวไม่ถือว่าเป็นการระงับบัญชี

## 5. กิจกรรม (Activities)

### วงจรสถานะ
```
DRAFT ──publish──▶ PUBLISHED ──▶ COMPLETED
  │                    │
  └───────cancel───────┴──────▶ CANCELLED
```
- **DRAFT (ฉบับร่าง)**: ยังไม่เปิดรับลงทะเบียน
- **PUBLISHED (เปิดรับลงทะเบียน)**: นิสิตลงทะเบียน/สแกนได้
- **COMPLETED / CANCELLED**: แก้ไขรายละเอียดไม่ได้
- **ลบกิจกรรม**: ADMIN ลบได้ทุกสถานะ รวมรายการที่มีผู้ลงทะเบียนแล้ว หลังยืนยันขอบเขตข้อมูลใน modal; ลบประวัติผู้เข้าร่วม เวลา QR ผู้ช่วยงาน ดาว และแบบประเมินที่ผูกกับกิจกรรมใน transaction เดียว และเก็บ Audit Log ไว้ ผู้จัดที่ไม่ใช่ ADMIN ลบได้เฉพาะ DRAFT ที่ไม่มีผู้เข้าร่วมหรือผู้ช่วยงาน

### การมองเห็นของนิสิต
- หน้า **เช็คอิน / เช็คเอาท์กิจกรรม** (`/dashboard/activities`) แสดงเฉพาะ `PUBLISHED` พร้อมปุ่มสแกน QR ตามสถานะเวลา ไม่มีปุ่มลงทะเบียนโดยตรง
- หน้า **กิจกรรมที่กำลังจะมาถึง** (`/dashboard` แสดงสูงสุด 4 รายการ, `/dashboard/upcoming` แสดงทั้งหมด) แสดงเฉพาะ `DRAFT` ที่ยังไม่ถึงเวลาสิ้นสุดในปีที่เลือก พร้อมป้าย "ฉบับร่าง" และไม่มีปุ่มลงทะเบียน

## 6. การลงทะเบียนผู้เข้าร่วม

- **นิสิตลงทะเบียนเอง**: `POST /api/activities/[id]/participations` (กิจกรรมต้อง `PUBLISHED`)
- **ผู้จัด/แอดมินเพิ่มให้**:
  - **ทีละคน**: จากหน้า `/scan` เมื่อสแกนแล้วยังไม่ลงทะเบียน จะมีปุ่ม "ลงทะเบียนกิจกรรมนี้แล้วเช็คอิน"
  - **หลายคน (bulk)**: หน้า `/admin/activities/[id]` หรือ `/organizer/activities/[id]` → ปุ่ม **"จัดการผู้เข้าร่วม/เวลา"**
    - ค้นหา (เว้นว่าง = ทั้งหมด), เลือกใน dropdown แบบหลายรายชื่อ, **"เลือกทั้งหมด"**, แล้ว **"เพิ่มที่เลือก (N)"**
- ยกเลิกการลงทะเบียนได้ถ้ายังไม่มีบันทึกเวลา

## 7. QR Check-in / Check-out

1. ผู้จัดสร้าง QR ที่หน้ารายละเอียดกิจกรรม เลือกประเภท (CHECK_IN/CHECK_OUT) และอายุ (นาที)
2. ระบบสุ่มโทเคน เก็บ `sha256` ลงฐานข้อมูล สร้าง **รูป QR** และ **ลิงก์** `…/scan?token=…`
3. หน้านี้มี **ตัวนับถอยหลัง** จนถึงเวลา `expiresAt` — หมดเวลาแล้วซ่อน QR อัตโนมัติ
4. กด **"ปิด QR ตอนนี้"** เพื่อ revoke ได้ทันที (สแกนต่อไม่ได้)
5. นิสิตสแกน:
   - **กล้องในแอป**: หน้า `/scan` → "เปิดกล้องสแกน" (ต้องเปิดผ่าน HTTPS หรือ localhost)
   - **หรือวางรหัส/ลิงก์** ในช่องกรอกของหน้า `/scan`
6. ระบบตรวจโทเคน → หา `Participation` → บันทึก `AttendanceRecord` (`method = QR`)
   - ซ้ำ → 409 · หมดอายุ/ถูกปิด → 400 · ยังไม่ลงทะเบียน → 400 พร้อมปุ่มลงทะเบียน
   - `CHECK_OUT` ต้องมี `CHECK_IN` ก่อน

## 8. การบันทึกเวลาของผู้จัด/แอดมิน (รายคนและ bulk)

ที่หน้ารายละเอียดกิจกรรม (`/admin/activities/[id]`, `/organizer/activities/[id]`):

- **รายคน**: ปุ่ม "บันทึก/แก้ไขเช็คอิน" และ "บันทึก/แก้ไขเช็คเอาท์" → เลือกวันเวลา (datetime) แล้วบันทึก (upsert)
- **ทั้งกิจกรรม (bulk)**: ในแผง "จัดการผู้เข้าร่วม/เวลา" → กำหนด **เวลาเช็คอิน / เวลาเช็คเอาท์** (เว้นว่างช่องที่ไม่ตั้งได้) → **"บันทึกเวลาให้ทุกคน"**
  - เช็คเอาท์จะตั้งให้เฉพาะคนที่มีเช็คอินแล้ว (คนที่ไม่มีจะถูกนับเป็น `skippedCheckOut`)

### คำนวณนาทีและดาวสีเหลืองอัตโนมัติ

- เมื่อมีเช็คอินและเช็คเอาท์ครบ คำนวณ `attendedMinutes = floor((เช็คเอาท์ − เช็คอิน) / 60,000)` จากเวลาจริงทั้งหมด รวมกรณีข้ามวัน ไม่ตัดตามกำหนดเวลากิจกรรม; 89 นาที 59 วินาที = 89 นาที
- นิสิต `STUDENT` ที่ผ่าน `minMinutes` (ค่าเริ่มต้น 90 นาที) ในกิจกรรม `PUBLISHED` หรือ `COMPLETED` ได้ดาวสีเหลือง `APPROVED` 1 ดาวอัตโนมัติ สูงสุด 12 ดาวต่อคนต่อปีการศึกษา แยกจากดาวสีเขียว; บันทึกเข้า–ออกครบแต่ไม่ถึงเกณฑ์เป็น `INCOMPLETE` และไม่ได้ดาว หากครบเพดานยังถือว่าผ่านเวลาแต่แสดงเหตุผลว่าไม่ได้ดาวเพิ่ม
- รองรับทั้ง QR บันทึกรายคน และ bulk; เวลา ผลประเมิน ดาว และ Audit Log บันทึกใน transaction เดียว ล็อกผู้ใช้เพื่อป้องกันคำขอหลายกิจกรรมให้ดาวเกินเพดาน และหนึ่งผู้เข้าร่วมได้ดาวสีเหลืองไม่เกินหนึ่งรายการต่อกิจกรรม
- ผู้จัดแก้เวลาแล้วจะคำนวณใหม่ หากไม่ผ่านเกณฑ์อีกต่อไป ดาวเดิมเปลี่ยนเป็น `REJECTED` โดยเก็บรายการและ Audit Log ไว้ ไม่สร้างดาวซ้ำหรือดาวติดลบ; ปฏิเสธเวลาออกก่อนเวลาเข้า
- เปลี่ยนเกณฑ์นาทีหรือสถานะกิจกรรมจะคำนวณผู้เข้าร่วมใหม่ รวมถึงยกเลิกดาวเมื่อกิจกรรมถูกยกเลิก **ADMIN ไม่ต้องกดคำนวณในการทำงานปกติ** ปุ่ม **"ตรวจสอบเวลา/ดาวอีกครั้ง"** เป็นเครื่องมือประเมินซ้ำเท่านั้น
- ข้อมูลเดิมก่อนเปิดฟีเจอร์ที่มีเวลาเข้า–ออกครบแต่ยังไม่มีนาทีสรุป ใช้ `backfillAttendanceResults` ประเมินด้วยกติกาเดียวกันใน transaction พร้อมบันทึก `attendance.backfill` เป็นการทำงานของระบบ (actor เป็น null); ข้ามรายการที่คำนวณแล้วและไม่ให้ดาวซ้ำ
- หน้ารายชื่อผู้เข้าร่วมและกิจกรรมของฉันแสดงนาที ดาว และเหตุผล; หลังสแกนเช็คเอาท์แสดงผลคำนวณทันที และหน้าภาพรวมแสดงยอดดาวสีเหลืองของปีที่เลือก

## 9. แดชบอร์ดนิสิต

- **ภาพรวม** (`/dashboard`): เลือกปีการศึกษาได้จาก dropdown และบันทึกปีที่เลือกใน URL (`?academicYearId=...`); ค่าเริ่มต้นใช้ปี `ACTIVE` ถ้าไม่มีใช้ปีล่าสุด ถ้ายังไม่มีปีการศึกษาแสดงตัวเลข 0 พร้อมข้อความแจ้ง
  - **เวลาเข้าร่วมรวม**: รวมนาทีเต็มจากเช็คอิน–เช็คเอาท์จริงของนิสิตในปีที่เลือก โดยไม่รวมกิจกรรมยกเลิก บันทึกเวลาไม่ครบ หรือเวลาที่ไม่ถูกต้อง; แสดงได้แม้ข้อมูลเดิมยังไม่มีค่า `attendedMinutes` โดยไม่เขียนข้อมูลหรือให้ดาวเพิ่มขณะเปิดหน้า
  - **กิจกรรมที่เข้าร่วมปัจจุบัน**: การ์ดรายการเหนือชุดการ์ดสถิติ แสดงกิจกรรม `PUBLISHED` ในปีที่เลือกที่มี `CHECK_IN` ไม่ใช่เวลาในอนาคตและยังไม่มี `CHECK_OUT` พร้อมเวลาเช็คอิน สถานที่ และปุ่มสแกนเช็คเอาท์; ยึดบันทึกเช็คอินจริงโดยไม่กรองตามกำหนดเวลาเริ่ม–สิ้นสุด และไม่แสดงกิจกรรมที่ผู้จัดสิ้นสุดหรือยกเลิกแล้ว
  - **กิจกรรมทั้งหมด**: จำนวนกิจกรรมทุกสถานะในปีนั้น รวมฉบับร่าง กิจกรรมที่สิ้นสุดและยกเลิก ไม่จำกัดเฉพาะที่นิสิตลงทะเบียน; กดการ์ดเพื่อเปิดรายการและรายละเอียดของปีที่เลือกได้
  - **เข้าร่วมแล้ว**: มีบันทึก `CHECK_IN` และ `CHECK_OUT` ครบในกิจกรรมของปีนั้น จำนวนนี้ยังไม่ได้หมายถึงผ่านเกณฑ์นาทีหรือได้รับดาว
  - **กิจกรรมที่พลาดไป**: กิจกรรม `COMPLETED` หรือ `PUBLISHED` ที่ถึงเวลาสิ้นสุดแล้ว และนิสิตไม่มีบันทึก `CHECK_IN` รวมทั้งผู้ที่ไม่ได้ลงทะเบียนและลงทะเบียนไว้แต่ไม่มา; ไม่นับ `DRAFT` หรือ `CANCELLED` และไม่หักดาว กดการ์ดเพื่อดูรายการได้
  - **กิจกรรมที่ถูกยกเลิก**: จำนวนกิจกรรม `CANCELLED` ทั้งหมดในปีที่เลือก ไม่จำกัดเฉพาะที่ลงทะเบียน กดเพื่อดูรายการได้
  - **กิจกรรมที่บันทึกเวลาไม่ครบ**: หากกิจกรรมเป็น `COMPLETED` และนิสิตมีเช็คอินแต่ไม่มีเช็คเอาท์ แสดงการ์ดแจ้งให้นิสิตติดต่อผู้จัดตรวจสอบเวลา รวมถึงป้ายในหน้ารายการและกิจกรรมของฉัน ไม่เติมเวลาออกอัตโนมัติ ไม่นับเป็นเข้า–ออกครบหรือกิจกรรมที่พลาดไป และยังไม่ถือว่าผ่านเกณฑ์รับดาว; ผู้จัด/แอดมินบันทึกเวลาออกตามจริงผ่านเครื่องมือบันทึกเวลารายคน แล้วข้อความเตือนจะหายไป
  - แสดงการ์ดสถิติ 4 ใบ: กิจกรรมทั้งหมด / เข้าร่วมแล้ว / กิจกรรมที่พลาดไป / กิจกรรมที่ถูกยกเลิก และกิจกรรมฉบับร่างที่กำลังจะมาถึงสูงสุด 4 รายการ (เรียงตามวันเริ่มต้นใกล้สุด) พร้อมลิงก์ "ดูทั้งหมด (N)"
- **กิจกรรมตามปีการศึกษา** (`/dashboard/year-activities`): แสดงกิจกรรมทุกสถานะพร้อมรายละเอียด วันเวลา สถานที่ เกณฑ์นาที และประวัติเช็คอิน/เอาท์ของตนเอง; เลือกปีและกรอง `all` / `missed` / `attended` / `cancelled` ได้ ลิงก์กลับภาพรวมคงปีที่เลือกไว้
- **กิจกรรมที่จะมาถึง** (`/dashboard/upcoming`): เฉพาะรายการ `DRAFT` ที่ยังไม่ถึงเวลาสิ้นสุดในปีที่เลือก; จำนวนบนปุ่มดูทั้งหมดใช้เงื่อนไขเดียวกัน และลิงก์ไป–กลับคง `academicYearId` ไว้
- **เช็คอิน / เช็คเอาท์กิจกรรม** (`/dashboard/activities`): การ์ดกิจกรรม `PUBLISHED` ไม่มีปุ่มลงทะเบียนโดยตรง พร้อมปุ่ม
  - ยังไม่เช็คอิน → **"สแกน QR Check-in"** → หน้า `/scan`
  - เช็คอินแล้วแต่ยังไม่เอาท์ → **"สแกน QR Check-out"**
  - ครบแล้ว → **"บันทึกเวลาครบแล้ว"** (แสดงเวลาเช็คอิน/เอาท์)
- **กิจกรรมของฉัน** (`/dashboard/my-activities`): รายการที่ลงทะเบียน + สถานะ + เวลาเข้าออก พร้อมบล็อก **"สรุปเวลาเข้าร่วม"** แสดงนาทีจริง เทียบเกณฑ์ของแต่ละกิจกรรม และดาวที่ได้รับ คำนวณเวลาแสดงผลจากบันทึกเข้า–ออกโดยตรง จึงรองรับบันทึกเก่าที่ช่องสรุปนาทียังว่างด้วย ข้อมูลดาวยังยึดผลประเมินที่บันทึกไว้

## 11. หน้าช่วยเหลือ

- `/forbidden` — 403 เมื่อไม่มีสิทธิ์
- `proxy.ts` — เด้งผู้ใช้ตามสถานะล็อกอิน/สิทธิ์ก่อนถึงหน้าเพจ

## 12. UI และข้อความแจ้งผล

- ใช้ shadcn/ui (Base UI) สำหรับปุ่ม การ์ด ตาราง ช่องกรอกข้อมูล ฟอร์ม Dialog และ Alert Dialog พร้อมธีมเขียวอมฟ้า
- ฟอร์มสร้างกิจกรรม เพิ่ม/แก้ไขปีการศึกษา แก้ไขผู้ใช้ เพิ่มผู้เข้าร่วม และบันทึกเวลา เปิดใน modal ที่เลื่อนได้บนหน้าจอขนาดเล็ก
- ใช้ `ConfirmDialog` ยืนยันการลบ เปลี่ยนสถานะกิจกรรม เปิด/ปิดปีการศึกษา เปลี่ยนบทบาทหรือระงับบัญชี ปิด QR ยกเลิกลงทะเบียน และออกจากระบบ
- ระหว่างยืนยันคำขอ แสดงสถานะกำลังดำเนินการและป้องกันการกดย้ำหรือปิดหน้าต่าง; หากคำขอล้มเหลว คงหน้าต่างไว้ให้ลองใหม่
- แจ้งผลสำเร็จ/ข้อผิดพลาดด้วย Sonner toast; ข้อผิดพลาดในฟอร์มเข้าสู่ระบบ สมัครสมาชิก และสแกน QR แสดงเป็น Alert ในหน้า
- การ์ดกิจกรรมแสดงปุ่มสแกน QR Check-in แม้ยังไม่ได้ลงทะเบียน; หากสแกนแล้วไม่มีรายชื่อ หน้า `/scan` มีขั้นตอนลงทะเบียนแล้วบันทึกเวลาให้ตามเดิม
- เมนูบนมือถือใช้ Dialog รองรับการใช้แป้นพิมพ์และจัดการ focus; modal มีชื่อและคำอธิบายสำหรับโปรแกรมอ่านหน้าจอ
